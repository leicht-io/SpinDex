# SpinDex Carrier Board

A custom PCB that piggybacks the M5Stack STAMP-S3M module on one side and
implements the TCRT5000 reflective IR sensor + comparator circuit directly
on the other, replacing the hand-wired FC-51/TCRT5000 breakout + jumper
wires with a single board sized to mount precisely against the Beogram's
strobe ring.

Built with KiCad 9. Everything in this folder was generated by script (see
"How this was built" below) and validated with `kicad-cli` (ERC/DRC both
pass clean) — **but it has not been opened in the KiCad GUI or physically
verified yet.** Do the checks in "Before you fabricate" first.

## Files

- `carrier-board.kicad_pro` / `.kicad_sch` / `.kicad_pcb` — the project
- `spindex.kicad_sym` — custom symbols: `STAMP-S3M`, `TCRT5000`
- `spindex.pretty/STAMP-S3M_DIP28_P1.27mm.kicad_mod` — custom footprint
- `sym-lib-table` / `fp-lib-table` — project-local library table, adds only
  the `spindex` library; everything else (Device, Comparator, OptoDevice,
  Connector_JST, etc.) resolves from KiCad's standard global libraries

## What's verified vs. estimated

**Verified directly from primary sources:**
- STAMP-S3M's full 28-pin pinout (pin number → signal name) — read
  directly from M5Stack's own module schematic
  ([Sch_M5StampS3_v0.2.pdf](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/522/Sch_M5StampS3_v0.2.pdf))
- 1.27mm pin pitch, 26×18×5mm module body (M5Stack docs/product listings)
- TCRT5000 pin assignment (1=Collector, 2=Emitter, 3=Anode, 4=Cathode) —
  read directly from the [Vishay TCRT5000 datasheet](https://www.vishay.com/docs/83760/tcrt5000.pdf)'s
  top-view pin diagram
- The `OptoDevice:Vishay_TCRT5000` footprint is KiCad's own standard
  library part for this exact component — not custom-made

**NOT verified — check before fabricating:**
- **Row-to-row pad spacing on `STAMP-S3M_DIP28_P1.27mm`, set to 15.24mm.**
  No source gives this dimension; it's sized to fit inside the module's
  known 18mm body width with plausible margin, nothing more. **Measure the
  actual module with calipers and update `ROW_SPACING` in
  `gen_footprint.py` (or edit the footprint directly) before ordering
  boards.** Getting this wrong means the module's pins won't line up with
  the holes.

## The circuit

- **Power:** none of this board's business, deliberately. The M5StampS3
  module (the assembled product, not just the bare chip-module inside it)
  has its own onboard USB-C connector and 5V→3.3V regulator — confirmed
  from M5Stack's own schematic, which shows the USB-C port, ESD protection,
  and DCDC regulator as part of the same board the 28-pin header lives on.
  Power it over USB-C like you would to flash it, and its `3V3` pin (typed
  `power_out` in the symbol, since the module is genuinely sourcing that
  rail) feeds the sensor circuit directly. `5V` on the header is a no-connect
  here — it's an available breakout on the module, not something this board
  drives. There's no separate power connector or regulator on this board at
  all; earlier drafts had a JST-PH power input and a bulk cap, both removed
  once it was clear the module's own USB-C already covers it.
- **Sensor front end:** D1 (TCRT5000) — R1 (220Ω) limits the IR LED
  current; R2 (10kΞ) pulls the phototransistor's collector up to 3V3,
  forming a voltage divider whose node (`PHOTO_C`) swings toward GND when
  a reflective bar is under the sensor.
- **Comparator:** U2 (LM393, referenced via its base `LM2903` symbol —
  same part, see below) compares `PHOTO_C` against a threshold set by
  RV1 (10kΩ trimmer, wired 3V3–GND with the wiper feeding the comparator's
  `-` input). Output idles HIGH (pulled up by R4) and drops LOW when a
  reflective bar is detected — **same polarity as the wired TCRT1000/FC-51
  setups this replaces, so `arduino_target.ino`'s edge-detection logic
  works unchanged.** The comparator's second (unused) gate has both inputs
  tied to GND so it can't float/oscillate; its output is left unconnected.
- **Status LED:** D2 + R3, lights when the sensor output is LOW (i.e. a
  bar is detected) — handy for bench-checking alignment without a scope.
- **EN/Boot pull-ups, no buttons:** R5 (10kΩ, `EN`) and R6 (10kΩ, `G0/Boot`)
  hold both pins at a defined HIGH so the module boots and runs normally.
  No manual reset/boot-select switches on this board — flashing means
  reconnecting USB-C to the module directly (same as any bare module),
  not pressing a button here.

### Why `Comparator:LM2903` instead of `LM393`

KiCad's `LM393` symbol is defined via `(extends "LM2903")` — it only holds
property overrides and depends on `LM2903`'s own graphics/pins to actually
render. Referencing `LM2903` directly avoids needing to also embed the
base symbol just to satisfy the alias, while remaining the same physically
interchangeable dual-comparator part; the schematic's `Value` field is set
to "LM393" so the BOM reads correctly.

## Layout

Two zones, as asked for — StampS3 on the left, TCRT5000 + comparator front
end on the right, on one board:

```
[R5]                        [D1 TCRT5000]
[R6]       [U1 STAMP-S3M]   [R1][R2]
                            [RV1]
                            [U2 LM393][C2]
                            [R4][R3]
                            [D2 status]
```

The board outline is currently just a bounding rectangle around all
components with room to breathe — **not a final shape.** Once the
enclosure is designed (or if it already exists in `../../3d-files/`),
reshape `Edge.Cuts` in the PCB editor so the sensor end sits where the
enclosure needs it relative to the platter, then trim the rest of the
board down from there.

## Before you fabricate

1. **Measure the actual STAMP-S3M module with calipers** and correct
   `ROW_SPACING` in `spindex.pretty/STAMP-S3M_DIP28_P1.27mm.kicad_mod` if
   it doesn't match 15.24mm.
2. **Open in KiCad and run "Update PCB from Schematic"** (Tools menu, or
   the equivalent toolbar button) — this syncs the netlist from the
   ERC-clean schematic onto the PCB and lights up the ratsnest. This
   wasn't done here on purpose: hand-duplicating the netlist into the PCB
   file risked a silent mismatch between the two; letting KiCad's own
   sync do it means there's exactly one source of truth (the schematic).
3. **Route the board.** Nothing is routed yet — only placed. A scripted
   auto-routing attempt was made (A* pathfinding with F.Cu/B.Cu+via
   fallback for congested spots) and got every net to *find* a path with
   0 unconnected nets, but kept surfacing new clearance/via-crowding
   violations faster than they could be cleanly resolved blindly —
   routing is fundamentally an interactive, visual-feedback problem
   (that's why every PCB tool has a live-DRC GUI for it) in a way
   placement and schematic capture weren't, and continuing to iterate
   on it without that feedback stopped being productive. With 12
   components and mostly low-speed signals this is a reasonable board to
   route by hand in an evening — KiCad's interactive router (push-and-
   shove, hotkey `X`) makes this fast once nets are synced from the
   schematic (step 2). There's no RF-critical routing here *except* keep
   the area over the STAMP-S3M module's antenna (top-right corner of its
   footprint, matching its silkscreen orientation) clear of copper and
   other components per M5Stack's own schematic — check their PDF for
   the exact keepout if you want to be precise about it. Also worth
   knowing: the layout was widened from an earlier pass to make room
   once real pad sizes were checked (routing revealed the initial
   spacing was tighter than the components actually need) — reasonable
   starting positions, not final.
4. **Tidy the schematic visually.** It's electrically correct (0 ERC
   violations) but was laid out programmatically — labels and component
   text overlap in places. Purely cosmetic; a few minutes of dragging
   things apart in the schematic editor fixes it, no netlist risk.
5. Reshape the board outline to the final enclosure, as above.
6. Re-run `kicad-cli sch erc` / `kicad-cli pcb drc` after any changes.

## BOM

| Ref | Part | Value | Footprint |
|---|---|---|---|
| U1 | M5Stack STAMP-S3M | — | `spindex:STAMP-S3M_DIP28_P1.27mm` |
| D1 | Vishay TCRT5000 | — | `OptoDevice:Vishay_TCRT5000` |
| U2 | LM393 (or LM2903) | dual comparator | `Package_DIP:DIP-8_W7.62mm` |
| RV1 | Trimmer potentiometer | 10kΩ | `Potentiometer_THT:Potentiometer_Bourns_3296W_Vertical` |
| R1, R3 | Resistor | 220Ω | `Resistor_THT:R_Axial_DIN0207_L6.3mm_D2.5mm_P10.16mm_Horizontal` |
| R2, R4, R5, R6 | Resistor | 10kΩ | same |
| C2 | Ceramic capacitor | 100nF | `Capacitor_THT:C_Disc_D3.0mm_W2.0mm_P2.50mm` |
| D2 | LED (status) | — | `LED_THT:LED_D3.0mm` |

All through-hole, hand-solder friendly. No power connector, regulator, or
buttons on this board — power and programming both go through the
M5StampS3 module's own USB-C port. Total BOM cost is a couple of dollars
in passives plus the STAMP-S3M module and TCRT5000 sensor themselves.

## How this was built

Every file here was generated by small Python scripts rather than
hand-typed — KiCad's `.kicad_sym`/`.kicad_sch`/`.kicad_pcb` S-expression
formats are precise enough that hand-authoring them risks subtle,
hard-to-spot mistakes (a wrong fill-type value, a flipped Y-axis sign
between library space and page space) that only show up as ERC/DRC
failures or, worse, silently-wrong connectivity. The generator scripts
aren't included in this folder (they were scratch tooling, not something
meant to be re-run), but the process was: generate → validate with
`kicad-cli sch erc` / `kicad-cli pcb drc` → fix → repeat until both came
back clean, plus rendering to SVG/PNG at each stage to visually sanity
check symbol/footprint graphics. Final state: **0 ERC violations, 0 DRC
violations.**
